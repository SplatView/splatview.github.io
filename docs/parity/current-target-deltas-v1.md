# Current target contract mapping v1

[The CSV inventory](current-target-deltas-v1.csv) contains 32 source-reviewed contracts for browser work against desktop SplatView 0.12.116. It covers the current selection boundary actions, pivot placement, export variants, alignment, settings, tutorial/onboarding and removed measurement controls. It is a bounded contract inventory, not a complete desktop control catalog.

The authority is successful Capture02 at [reference/targets/windows-r0-20261012-02/source](../../reference/targets/windows-r0-20261012-02/source). Its recorded tree SHA-256 is `162c4bb2b129dc49169b3678e21b1b607a13bfd249f75cb1a2b3a5b7e8e9a2f4`. The captured [CMakeLists.txt](../../reference/targets/windows-r0-20261012-02/source/CMakeLists.txt) declares 0.12.116 and has SHA-256 `7255cf561615136a965a7b37dc6d88aba5020dde9109a213a575b45d0de724cd`. All 25 selected file hashes observed during the initial live review matched this frozen capture. The inventory's primary and supporting references were rebound to Capture02; no final reference points at the mutable sibling source tree.

Historical `reference/windows` locks, source labels and runtime receipts keep their original provenance. Capture01 is not this inventory's authority. No exact 0.12.115 snapshot was compared, so these rows do not attribute a change specifically to the 0.12.116 release.

| CSV fields | Meaning |
| --- | --- |
| `contract_id`, `area`, `delta_kind` | Stable mapping key and scope. Added/changed/removed is relative to the historical frozen reference; retained rows record adjacent contracts needed for implementation. |
| `source_snapshot`, `source_tree_sha256`, `target_cmake_sha256` | Target-source identity. These are distinct from a compiled native or browser build identity. |
| `source_path`, `source_line`, `source_symbol`, `source_sha256` | One primary frozen source anchor and its exact file digest. `supporting_anchors` lists related frozen lines; `baseline_reference` remains historical. |
| `basic_available`, `pro_available`, `enabled_rule` | Mode availability plus runtime gating. A true value means the contract applies in that mode; it does not prove a browser implementation exists. `removed` means the current target omits that control. |
| `desktop_contract`, `browser_boundary` | Observed desktop rule and the browser responsibility to preserve it. Browser boundaries are integration requirements, not claims of implemented behavior. |
| `fixture_id`, `fixture_spec`, `acceptance_criteria` | Stable IDs for independent acceptance fixtures to implement. These are specifications; no fixture execution is claimed. |
| Status fields | Source review is complete for this inventory. Native, browser and Mac acceptance remain `pending;not-run`; browser implementation is `not-assessed-in-R0`. |

The browser mapping follows existing responsibilities: [App.tsx](../../src/ui/App.tsx) presents controls; [controller.ts](../../src/app/controller.ts) owns document interactions; [store.ts](../../src/app/store.ts) separates UI preferences and display state; [coreClient.ts](../../src/document/coreClient.ts) transports admitted operations; [types.ts](../../src/document/types.ts) carries document/source/content/selection/draft revisions. This mapping does not assign a new public WASM API or imply that new commands already exist.

Independent fixture specifications include analytic sphere chains and separately solved ellipsoid contact, explicit expected masks/history, an independent SPZ reader, analytic coordinate/camera transforms, and DOM preference/focus sequences. Tests that simply call the same algorithm twice do not establish parity. Deferred result, cancellation, failure, exhausted history-budget and resource-retirement cases are part of the acceptance contract. Format-memory fixtures also reopen the chooser after failed/canceled encoding; canceling the chooser itself preserves the previous choice.

Source review and machine-readable reference checks establish only this inventory's binding. They do not establish compiled native acceptance, browser runtime parity, matched desktop/browser images, actual Mac Safari/Chrome behavior, or VoiceOver qualification. No public WASM namespace enumeration or traversal was performed. Platform-specific Explorer thumbnail, Windows Default Apps and Microsoft Store updater behavior needs a recorded browser difference; the About dialog must display actual browser build provenance separately from the target desktop source version.
