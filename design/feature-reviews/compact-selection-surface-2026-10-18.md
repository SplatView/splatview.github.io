## Intent, semantics and ownership

The existing WebGPU path reserves and sorts `tileCount × maximumTileCapacity` entries, including empty tiles, retries allocations/projection when the initial capacity overflows and refuses more than 8,192 candidates in a tile. Replace this with a count-first compact layout: count projected candidates, plan individual power-of-two tile spans, allocate only these spans, fill once and sort each tile's own span. Empty tiles require no candidate entries or sorting. Remove the default fixed per-tile ceiling; device buffers, safe index arithmetic and the existing resource ledger still admit or refuse the complete query. Explicit test/caller ceilings remain supported.

Preserve every surviving fragment in stable global depth order, FP32 composited depth/opacity, raw view-dependent SH color, full-frame contributing-source visibility and partial edge tiles. Do not substitute frontmost picking, drop rear contributions or change desktop Fill/connected Color semantics. Reuse `DocumentSelectionMaps`, immutable frame snapshots, cancellation and the existing native map adoption/history owner. The first readback remains small and tile-sized. Every asynchronous boundary rechecks scene/view/device identity; all queued work retires before memory credit or GPU allocations are released. A refused query must not publish a partial map or change selection, edits, source files or Undo/Redo.

Affected Basic tools are 3D brush, visible-only screen brush, Fill and connected Color. Ordinary picking, display rendering, file decoding, capture and saved views retain their current owners. No controls, translations, tutorial targets, settings, API/CLI commands, wire formats or product registrations change. Web-lite still excludes an agent server and advanced editing.

## Implemented behavior and measured workload

`surfaceLayout.ts` validates compact prefix offsets and device-sized candidate storage before upload. `surface.ts` counts once, reads tile counts, admits the complete compact allocation, fills once and retains only the requested CPU channels after GPU retirement. `surface.wgsl` shares the footprint function between count and scatter, sorts spans up to 1,024 entries in workgroup memory and uses storage sorting for larger spans. Uniform span publication and overflow-safe sort-loop termination preserve WebGPU barrier/index requirements. Empty tiles have zero entries; a four-byte physical buffer supplies the valid empty binding. Optional explicit caller ceilings remain, while normal selection no longer has the 8,192 ceiling.

The source changes are original SplatView work. The [SuperSplat reference record](../../docs/third-party/PLAYCANVAS_SELECTION_REFERENCES.md) cites pinned PlayCanvas 3.5.2 sources at `f2a1b4975b4766e0ee0c95e63c2737dc2ecb6e5b` and its MIT license. It distinguishes their GPU ID/mask intersection and bounded readbacks from our all-fragment blended map; no SuperSplat source code was copied. Existing query caching, renderer order, controller/native adoption, worker, scene/history and save owners remain.

The same immutable `measure-surface-01.mjs` helper was run before and after on Windows Chromium 156.0.8078.4, secure localhost. The localized-density fixture contains 2,273 splats and a 512 × 512 viewport. Across three measurements after two warmups, end-to-end fixture/query wall-time medians were **13.2 ms before and 10.4 ms after** (about 21% lower). This includes fixture GPU allocation/upload, sorting and surface readback; it is not a GPU timestamp or an isolated selection-kernel measurement. The old path allocated 1 MiB, retired it, then allocated 16 MiB of candidates; the new path allocated **67,264 bytes once** (65.7 KiB). The cold first observations were 114.2 ms and 133.3 ms respectively; this packet does not claim faster cold shader/pipeline creation.

All five baseline 8,193-overlap queries reproduced the old refusal; all five optimized queries succeeded. That timing fixture tests admission, while a separate 511 × 511 analytic fixture establishes actual surviving center fragments, blended depth/raw color and source-visibility bits above the former ceiling. Sparse/dense, entirely empty and legacy-initial-hint fixtures check actual candidate buffer allocations, sorting work, memory retention and cleanup. The sparse fixture independently accounts for three grid overlaps absorbed into existing dense spans, rather than charging new singleton entries.

These are bounded workload observations, not SuperSplat-equivalent capacity, physical VRAM measurement or a universal frame-rate guarantee. Exact dense composition still costs work proportional to actual overlapping candidates/pixels and remains conditional on device buffers and admitted resources.
