## Findings and intended workflow

The only existing Actions workflow is GitHub's generated Pages builder. The
default branch is the static `main`, while development is on `source`. A fresh
checkout needs explicit frozen-reference restoration and untracked native
publication files; the reviewed native compiler/tool cache is Windows-specific.
Publishing currently uses scripts retained only in ignored release directories.

- Add a single explicit setup command that restores the local frozen-reference
  ZIP, restores a checksum-pinned already qualified WASM runtime when needed,
  verifies its freshness with the existing unchanged native verifier, and
  installs locked npm dependencies. Add read-only doctor diagnostics and a
  shared local/CI validation command with fresh ignored logs/receipts.
- Pin the frontend Node version already used in this workspace. Keep package,
  dependency, native source/toolchain and compiler/cache locks unchanged.
  Restoring reviewed runtime bytes is not fresh native compilation. Native
  changes must refuse an outdated seed and retain the locked Windows build path.
- Add PR/source-push CI on Windows and Ubuntu: project/product/source/native
  verification, both typechecks, Python/build-tool/full portable tests, app and
  standalone builds. Add bounded appearance/browser smoke coverage without
  calling software/no-GPU CI proof native GPU qualification. Upload logs on
  failure and built artifacts on success. Cache downloads, not trusted outputs.
- Add a manual deployment path, dry run by default, that promotes an existing
  published, immutable-version release. Verify its source tag/commit, package
  version, checksums, complete app/native manifest and source-derived build
  identity before staging. Preserve current publisher/legal files and older
  hashed assets; push only an isolated static checkout to `main`, without force.
  Request and verify the existing Pages build and verify public bytes when
  publication is explicitly selected. Do not deploy untrusted PR/CI artifacts.
- Change the repository's development default to `source` after workflows are
  present, preserving Pages `main:/` and all tags/history. This makes clone/PR
  defaults and manual workflow dispatch agree with the documented source branch.
  Verify actual hosted runs and exercise deployment in dry-run mode against
  the already published v0.2.2; this task does not publish a new app version.

Use least-privilege workflow permissions, immutable official action commit pins,
bounded concurrency/timeouts and no `pull_request_target` code execution.
GitHub Actions updates can use Dependabot against `source`. Do not introduce a
parallel build framework, another runtime owner or live sibling dependency.

registrations or agent-server features. There is no profile migration, telemetry
change, source overwrite, scene-format change, worker-budget change or renderer/
controller/history/submission/cancellation/retirement ownership change.

native publication leaves and existing freshness/identity checks. Do not walk
arbitrary `public/wasm` leaves or overwrite conflicting local runtime files.
Downloads are bounded and checksum verified before extraction; archive members

source/version/checksum and branch boundaries. Validate from a clean source
export without a local SDK, then run the shared checks locally and on hosted

Record actual checks/failures, host/browser/GPU/security context and limitations;
do not claim GPU or native qualification from portable tests alone. Raw evidence

## Implementation and local evidence

Implemented `setup`, read-only `doctor`, `check`, `ci`, tool regression tests,
the bounded UI-only Chromium profile, pinned official Actions, Windows/Ubuntu
source CI and read-only dry-run/write-enabled release-promotion jobs. The
maintained promotion verifier derives identities from tagged source data without
executing that tag's scripts. Maintainer entry points are documented in
`docs/development/automation.md`. No product/native registrations changed.

- Full local `npm run ci`: 6,480 portable tests in 213 files, 42 Node tests,
  129 Python tests (128 pass, one existing host skip), both typechecks, all
  source/product/generated/native/layout gates, app build and 63-artifact
  standalone build/isolated consumer passed. The sealed adapter retains 133
  registrations and does not claim native qualification.
- Fresh 1,935-file source export, with no dependencies, frozen-reference tree,
  native publication, SDK or evidence cache: setup restored 1,336 missing
  references, verified three already tracked references, downloaded the pinned
  v0.2.2 seed and installed the npm lock. Both app and standalone builds passed.
- Eleven UI appearance/update-notice browser cases passed, zero retries, on
  Windows Chromium 156 over secure localhost. The harness substitutes startup;
  it initializes no native worker, scene or GPU. No renderer/OS/GPU qualification
  is inferred from this lane. Theme tests retain their hardware lane.
- Local promotion dry run independently verified all 116 v0.2.2 distribution
  files and nine preserved publisher/legal files against static base
  `74f9a62f7caf580058a29dab9041fdee9f36fde4`; the staged diff was empty.
  No push, Pages request, new tag, version bump or release mutation occurred.
- `actionlint` 1.7.12 passed both workflows. Protected tracked native/reference/
  product/dependency inputs (551 files) remain byte-identical to the baseline.

Local checks exposed and resolved Windows redirected-output encoding and
Playwright's multi-config server/project merge behavior. Failed receipts/logs
were retained; they were not rewritten. The existing app chunk-size advisory
and one existing Python host skip remain. Hosted run and repository-default
verification will be appended after the workflows reach `source`.
