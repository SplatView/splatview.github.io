## Behavior and existing owners

- Prepare surface pipelines asynchronously and warm required pipelines after the first scene frame. Share in-flight preparation, defer optional visibility work until requested, and evict failed preparation. Do not mix outstanding asynchronous creation with unbalanced device error scopes. Observe preparation/counting/planning/allocation/composition/readback/CPU-copy/native-adoption wall times; these are not isolated GPU timestamps.
- Tighten conservative projected bounds using the fragment's exact ellipse/support/alpha rules with roundoff padding and conservative fallback. Count and scatter use the same helper. Preserve every accepted fragment, stable order, exact FP32 depth/opacity/color, top-left edges, extreme anisotropy and source visibility. No transmission early exit or quality reduction.
- Reuse only unmapped, fully retired, exact-size/usage GPU scratch buffers under an explicit bounded renderer owner and real resource leases. Clear reused counters, padded candidates and visibility outputs before use. Retained buffers remain charged, with eviction/pressure retry and scene/device teardown. Never release memory credit ahead of GPU retirement. Preserve the existing ledger, query/cache, native adoption and history ownership rather than inventing a second scheduler.
- Restrict partial depth maps to 3D brush commands with `visibleOnly=false`. Bound the entire accumulated physical-framebuffer path, not just its latest endpoint; include the nearest/interpolated depth halo and tile alignment. Preserve full map dimensions/projection and native array transport, with zeros outside coverage. Splats centered outside coverage still contribute when their footprints overlap it. Immutable coverage participates in cache/pending containment: full serves partial, partial cannot satisfy full, growing paths recompute sufficient union coverage, and full consumers upgrade safely. Fill, connected Color and global visibility remain full-coverage queries.

These are internal UI query paths only. No API/CLI command, native file save/overwrite, source mutation, tutorial, setting/default, selection meaning, document dirty state or history schema changes. Web-lite remains Basic, with no agent server or advanced editing. Reference sources are the existing [pinned SuperSplat attribution](../../docs/third-party/PLAYCANVAS_SELECTION_REFERENCES.md); no copied source is proposed.

## Completed implementation and qualification

All four optimizations are implemented under the existing renderer, document ledger, map cache, native adoption and controller/history owners. The renderer warms five shared asynchronous pipelines after its first actual scene frame; the sixth visibility pipeline remains lazy. Failed preparation is evicted and a real query can retry. GPU buffers have independent physical leases, remain charged while idle, and are capped at 16 MiB / 32 idle entries. Reused counters/candidate padding/visibility/partial output are cleared before use. Failure/cancellation retirement discards scratch, including cancellation during the final GPU join. Native-map adoption can evict optional idle scratch and retry its admission without double-crediting.

The brush region includes all accumulated physical stroke points, offscreen crossing segments, nearest/interpolated depth halo and conservative tile alignment. Full dimensions/projection/native arrays remain intact. Partial maps carry immutable coverage; contained requests reuse, growing requests recompute a union and Color/visibility requests require full coverage. Ambiguous coordinates/unsupported packed dimensions use the full path. No native/WASM, UI, file-format, product registration or source-lock changes were made.

Passed 6,255 CPU cases in 192 files, 126 focused development-browser cases and four production Basic/shipped browser cases, with zero retries. Both typechecks, production build, 919 pinned sources, generated assets/catalogs, product bundle 2.0.0 / 128 bindings and exact native artifacts pass. Browser evidence is Windows Chromium 156.0.8078.4 in a secure localhost context, reporting a nonfallback NVIDIA Blackwell adapter. No new Apple/native-provider qualification is claimed.

The independent old-full-quad GPU binning oracle compares every FP32 depth, opacity and raw-color pixel across 37 fixtures, including near-cutoff, anisotropic, rotated, offscreen, top-left, rounded nonorthogonal and downsampled cases. Differences are zero. Additional real GPU/native tests compare full/local depth and exact native masks/Undo/Redo at 320 × 200, 1,025 × 769 and physical DPR two, including taps, growing/diagonal paths, offscreen crossing and empty regions. Full-width partial-height readback and pooled empty output are exercised. Cache coverage upgrades, actual first-frame warming, lazy visibility, shared preparation and real controller brush dispatch pass. Pooled/fresh outputs agree exactly after camera, density/deletion and visibility changes; authenticated physical credit is kept separate from CPU/native/history and reaches zero on invalidation/teardown.

The immutable same-helper baseline was captured before production changes. With two warmups and three measured samples, warm fixture/upload/query/disposal medians changed from 15.2 to 11.6 ms for 2,273 sources and 22.1 to 14.7 ms for 8,193 sources. Candidate allocations changed 67,264 → 67,120 bytes and 262,144 → 262,144 bytes. Sample depth/opacity deltas are zero. The dense benchmark is an admission/work fixture, separate from the analytic 8,193-surviving-contributor proof. No universal improvement or isolated shader-compilation/cold-speed claim follows.

At a 1,025 × 769 framebuffer, the small tap's depth readback was 4,096 bytes versus 2,094,504 full-map bytes; CPU/native map transport remains full-sized. A 320 × 200 all-channel query initially created 13 scratch buffers; a subsequent camera query reused all 13 and created none, matching a separately allocated oracle. Stage profiles expose finite wall intervals for preparation/counting/planning/allocation/composition-readback/copy/retirement, plus native-adoption elapsed observations. They are not GPU timestamp measurements.
